Tool plugins

Integrate toolsTools written as Python scripts or Swift executables, discovered from ~/.arc/plugins/ (arc plugin parity). Enablement is stored in the plugins.enabled allow-list of ~/.arc/config.json.
No tool plugins found.
Drop a directory with a manifest.json into ~/.arc/plugins/<name>/ and press Rescan. Each tool is an executable (or interpreter + script pair, e.g. python3 + tool.py) that reads {"tool": name, "args": {...}} on stdin and writes {"result": "..."} on stdout. See docs/plugin-tools.md in the arc-agent repository for the full contract and examples.

MCP servers

External tool serversChild processes speaking the Model Context Protocol over stdio. The agent reaches every one of their tools through the single mcp_tool bridge; this panel owns the mcp_servers block of ~/.arc/config.json.
No MCP servers configured.
A server is a child process that speaks the Model Context Protocol over stdio — a local executable, usually built with swift-mcp. Once added it is started on first use, and the agent reaches its tools through the single mcp_tool bridge (Tools panel): ask the agent to call mcp_tool with action: "list" to see every server and tool. mcp_servers in ~/.arc/config.json is the source of truth, and this panel edits exactly that block. Arguments reach the process verbatim; nothing is run through a shell.
