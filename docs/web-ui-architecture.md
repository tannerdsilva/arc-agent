# Web UI Architecture

## Overview

The web UI is the `arc-agent-webui` executable target (`Sources/ArcAgentWebUI/`), built on the declarative **no-webui** engine (Swift DSL → HTML/CSS/JS). There is no npm, no node_modules, no build pipeline: every asset required by the UI is compiled into the binary as Swift strings.

## Layout

```
Sources/ArcAgentWebUI/
├── Entry.swift            — CLI entrypoint, HTML shell, asset/version wiring, CSP
├── Server.swift           — Hummingbird HTTP + WebSocket server, static/asset routes, WSIncoming
├── AppState.swift         — actor: sessions, settings, registry, runTurn orchestration, fragments
├── Actions.swift          — wire handlers (settings, approvals, queues, skills, agent powers)
├── Views.swift            — all page/section HTML builders (chat, sidebar, settings, skills, …)
├── Theme.swift            — full stylesheet as Swift constants, 27 color schemes
├── RuntimeAsset.swift     — client runtime JS (event routing, flyouts, drag-and-drop) as strings
├── Queue.swift            — run-queue model/engine (sequential + parallel, output chaining)
├── NewFeatures.swift      — tabbed panels, todos, cron, regenerate
├── Insights.swift         — usage insights (top-10 skills, token/activity charts)
├── Generated/
│   └── KaTeXAssets.swift  — KaTeX CSS/JS/fonts, base64-embedded (regenerated by
│                            `python3 Scripts/gen_katex_assets.py`, `make assets`)
└── Assets/vendor/katex/   — vendored KaTeX source files (input to the generator)
```

## Rendering pipeline

1. **Server-side**: message content is rendered to HTML by the shared Hermes-parity
   renderer in `Sources/ArcAgentCore/WebUI/Utilities.swift`
   (`markdownToHTML` / `MarkdownRenderer`) — ATX headings, pipe tables, nested
   blockquotes, task checkboxes, KaTeX math elements, sanitized images, autolinks.
2. **Client-side enhancement**: table sort/filter, KaTeX rendering of
   `<equation-inline>`/`<equation-block>` elements, drag-and-drop, flyouts, and
   composer features (slash autocomplete, reply-with-selection context chips).

## Asset policy

- **No npm, no exceptions.** CSS/JS are canonical Swift source (`Theme.swift`,
  `RuntimeAsset.swift`); KaTeX is generated from vendored files into
  `Generated/KaTeXAssets.swift` (base64 — immune to escaping issues).
- **Debug and release behave identically**: the same embedded strings serve both.
  No disk-serve routes exist for the UI.

## Shared renderers (ArcAgentCore/WebUI)

Only three files remain in `Sources/ArcAgentCore/WebUI/`:
- `Utilities.swift` — Hermes-parity `markdownToHTML`, `MarkdownRenderer`, `htmlEscape`, `sanitizeImageURL`
- `WebSocketHandler.swift` / `WebSocketServer.swift` — gateway WebSocket session channel

The original Swift-DSL view subsystem (View/ViewBuilder/HTMLDocument/CSSRule/…)
was removed in 2026-09 after the UI moved to no-webui — it had zero remaining
product references.
